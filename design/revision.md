# RevisionPipeline

Implementation: [revision.py](/src/pipelines/revision.py). English and Hindi are
separate single-task `RunContext` runs. The caller supplies the fixed pool and an
immutable English checkpoint to Hindi runs. The [API guide](/src/README.md) lists
the callable path and the experiment-runner controls still pending.

Owns `src/pipelines/revision.py`: `RevisionConfig` and `RevisionPipeline(PipelineBase)`. It runs the English stage and, for each arm, the Hindi stage, deciding **which English pool examples to replay and with what text**. It doesn't choose blocks or shrink adapters; that's [summarization-experiments.md](/design/summarization-experiments.md), applied through the model operations in [models.md](/design/models.md). The [plan guardrails](/design/summarization-plan.md) apply.

Experiments: X, A, B, G1, G2, G3, the compute-matched control, and the full-English reference, from [Idea_Refined_2.md](/Idea_Refined_2.md).

## Config

| Field | Values | Meaning |
|---|---|---|
| `stage` | `english`, `hindi` | Which stage this run performs |
| `selector` | `none`, `random`, `loss`, `drift`, `full` | X, A, B, G1, and the full-English reference |
| `replay_text` | `reference`, `past` | G2 uses `past` |
| `repair_stop` | `false`, `true` | G3 |
| `hindi_batch`, `replay_per_batch` | Required ints (pre-registered 16, 2) | Each update has `hindi_batch` Hindi rows plus `replay_per_batch` pool rows |
| `top_fraction` | Required (0.5) | Share of replay slots filled from the top of the ranking. The rest are random |
| `warmup_fraction` | Required (0.1) | Share of Hindi steps run with random replay before rescoring |
| `past_filter_fraction` | Required (0.2) | G2 drops this share of past summaries least similar to their reference |
| `repair_beta`, `stop_similarity`, `refresh_steps` | Required (1, 0.9, 200) | G3 |
| `extra_random_steps` | Int, default 0 | The compute-matched control only |
| `hindi_passes` | Required int | Same for every arm, fixed in the pilot |

`selector="none"` with `replay_per_batch` ignored is X. Unknown combinations are rejected by the config's own enum check, such as `replay_text="past"` with `selector="none"`.

## English stage

1. Train the adapter on all blocks with 2,000 English training rows for the configured passes. After each pass, evaluate English validation chrF, and keep the best pass. That's the **English checkpoint**.
2. Save it as an immutable artifact ([model-weights.md](/design/model-weights.md)). Every Hindi run of the same prefix variant loads it.
3. For each of the 500 pool rows (a seeded subset of the 2,000 English training rows), compute and store in `Record.practice`:
   - `answer_text`, `answer_ids`: the English checkpoint's greedy summary, up to 64 tokens. This is the **past summary**.
   - `baseline`: per-token NLL of the reference summary under the English checkpoint, flat over supervised tokens.
   - `past_baseline`: per-token NLL of the past summary under the English checkpoint.
   - `loss_before`: mean of `baseline`, the example loss `l_i(English checkpoint)` used by B.
   - `writer = "english_checkpoint"`.
4. Score English and Hindi on validation and test, with and without the script guard.

The pool and its practice data are one artifact. They're never regenerated by a model that was trained on them.

## Hindi stage

Load the English checkpoint and the pool. Apply the arm's `AdapterPlan` (default: all blocks trainable, no new room). Then:

```text
for each update:
  hindi = next hindi_batch rows of the Hindi training view
  if selector == "none":  batch = hindi
  elif selector == "full":  batch = hindi + next hindi_batch rows of the full English training set
  else:                   batch = hindi + replay_slots(replay_per_batch)
  loss = mean over all rows in the batch of (- log p(target | article))     (per-example mean)
```

The objective is the **per-example mean over the combined batch**, as stated in the plan. That differs from CSReL's separately normalized current and replay terms, so it's recorded as such. Hindi exposure is the same for every arm. Extra English work is recorded as tokens and time.

The Hindi stage has no early stopping. It runs the fixed number of passes, so no arm stops at a different point.

### Replay slots

Before the warm-up ends (the first `warmup_fraction` of Hindi steps), every selector fills slots at random from the pool. At the end of the warm-up, rescore once, without changing the weights. After that:

```text
top  = ceil(top_fraction x replay_per_batch) slots from the ranking, in order, cycling when exhausted
rest = slots drawn uniformly at random from the pool, excluding rows already in this batch
```

| Selector | Ranking after warm-up |
|---|---|
| `random` (A) | None: every slot is random |
| `loss` (B) | `Δl_i = l_i(now) - loss_before_i`, highest first. `l_i` is the mean target-token NLL of the reference summary |
| `drift` (G1) | `d_i = 1 - chrf(new_i, past_i) / 100`, highest first. `new_i` is the model's greedy summary now. If `script_share(new_i) > 0.5`, the row has slipped and `d_i = 1` |

Ties break by stable sample ID. Rescoring reads the learner through `score` and `predict`, so it isn't an update, and it records its cost (B: pool scoring; G1: pool generation).

**Diagnostics:** save the full ranking with scores for B and G1. The experiment runner computes `top_overlap` between them.

### Replay text

| `replay_text` | Replayed target |
|---|---|
| `reference` | The stored reference summary |
| `past` (G2) | `practice_record(record)`: the past summary, same `sample_id` |

**G2's filter**, applied once before the Hindi stage. A past summary is kept if all hold:

```text
script_share(past) <= 0.5,   word count >= 5,
chrf(past, reference) is not in the pool's lowest past_filter_fraction
```

Dropped rows are never replayed. Their count is reported. Selection then draws only from kept rows.

### Repair and stop (G3)

G3 runs on the parent selector (`loss` or `drift`, whichever wins on validation by the [winner rule](/design/summarization-experiments.md)), with `replay_text` unchanged.

**Repair weights.** For a replayed row with per-token NLL `s_now` and stored baseline `s_before` (`baseline` for references, `past_baseline` for past text):

```text
w_t = 1 + repair_beta x max(0, s_now_t - s_before_t)
w   = w / mean(w)                                   (average weight 1 per row)
```

This is `log p_before - log p_now` written as NLL. The batch uses `Objective.token_mode = "weighted"` and `TokenTargets(weight=w)`. Hindi rows get weight 1. `s_now` is taken detached from the same forward pass, before backward.

**Stop rule.** Keep an active set: the rows replay would currently draw from the ranking. Every `refresh_steps` updates, the learner rewrites each active row's article greedily:

```text
if chrf(new, past) / 100 >= stop_similarity and script_share(new) <= 0.5:
    the row retires: it leaves the ranking, and the next-ranked row takes its place
```

Retired rows can still appear in the random half of the slots. Report the count retired, the step each retired, and the regeneration time.

**Not in G3:** the earlier recipe's repair test with rollouts, the hinge baseline, and sentence cuts ([repair-stop.md](/design/repair-stop.md)). They're not part of this plan.

## Compute-matched control

`selector="random"` with `extra_random_steps > 0`. After the normal Hindi passes, run that many extra updates (16 Hindi plus 2 random pool rows each). The runner sets `extra_random_steps = ceil(G1's measured generation seconds / A's measured seconds per update)`, using the same seed's runs. If this ties G1, G1's gain came from compute, not from better choices.

## Capabilities

| Capability | Input -> output |
|---|---|
| `write_past` | Pool records -> records with `practice` set |
| `rank_pool` | Pool, selector -> ordered IDs with scores |
| `replay_slots` | Ranking, slot rule -> ordered sample IDs for one batch |
| `retire` | Active rows, regenerated summaries -> retired IDs |
| `token_targets(batch)` | Replay rows -> `TokenTargets` when `repair_stop`, otherwise `None` |

Proposals never mutate the pool. The lifecycle owner, this pipeline in its standalone run, commits the past-summary artifact once at the end of the English stage.

## State and resume

Policy state holds the ranking, the active set, retired IDs, the warm-up and refresh cursors, and the component RNG, all as plain JSON. Each long loop (writing past summaries, rescoring, regeneration) checkpoints after every batch. A resumed run never redraws a pending slot.
